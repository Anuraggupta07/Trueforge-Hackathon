Altitude 1 · system context

Who talks to whom

You chat with a TrueForge agent. The agent can reach AWS only through Warden's MCP server, which holds the AWS credentials, runs the Watchdog and writes the ledger. The Daytona sandbox runs proof scripts and never holds cloud or model keys.

  • The server is warden.server:main, a FastMCP app on streamable HTTP at /mcp (port 8000). The same process serves the read-only console at /console, /console/api/state and /console/api/simulator.
  • TrueForge pauses on 10 tools. agent/setup_agent.py registers the MCP server and lists every action and undo tool in require_approval_for_tools.
  • The Watchdog is independent code, not a separate machine. It never imports the Executor, re-reads AWS with its own calls and signs a single-use HMAC slip that actions.py must consume before it acts.

Where the code and the docs disagree
  • quarantine_volumes and recycle_snapshots are annotated destructiveHint=True, although both can be undone. stop_instances, quarantine_addresses and the four undo tools use destructiveHint=False. Approval still works, because TrueForge gates the 10 tools by name.
  • watchdog_verify is annotated readOnlyHint=True, but it writes a sign-off file and a ledger entry.
  • The README's architecture sketch lists a "receipts" tool. The code registers get_plan, get_receipt, list_receipts and list_warden_backups instead; the total of 19 matches.
